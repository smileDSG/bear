# 阅读负担与交互（12m_v1）

这份文档管两件事：**玩家必须读多少字**，以及**这些字凭什么非读不可**。句式怎么写归《对白与文风》；剧情事实归三册。这里只定“删什么、留什么、删了以后靠什么接住”。

## 0. 一句话口径

减字只减三类：**重复交代、提前预告、替玩家总结**。
人物台词、现场细节、每场那句闲话，一个字不动——那是体验感本体。

## 1. 账本（2026-10-30 实测，全部来自 `data/story/v12m/`）

| 来源 | 体量 | 必读？ |
|---|---|---|
| 剧情正文 | 520 拍 / 14,540 字 | 是 |
| 选项结果 | 118 条 / 3,979 字（实际只读到 1/3） | 是 |
| 屏末交代 `departNote` | 16 条 / 365 字，另有自动补句 | 是 |
| 今天卡 + 活动卡 | 25 张 / 1,050 字 | 是 |
| 手机消息 | 31 条 / 887 字 | 是 |
| 提示条 | 36 条 / 716 字 | 半 |
| 手册 | 约 1,600 字 | 可选 |
| **合计** | **≈1.85 万字 / 60 分钟纯读 / 638 次点击** | |

结论：总字数对一个 3–5 小时的叙事游戏不算离谱，**问题在密度和重复**——同一条安排一个月被讲 2–3 遍（第 2 月“去树影书院查旧单”散在 5 个屏里说了 9 次），且玩家全程只有“点”。

## 3. 必留清单（K）

| 编号 | 类型 | 说明 |
|---|---|---|
| K1 | 人物声线台词 | 每场至少 3 句能听出是谁在说的 |
| K2 | 现场细节 | 灯、纸角折痕、假绿植、包子——不承担信息，承担可信度 |

| K4 | 屏末落点 | 每屏最后仍要说清“谁安排、去哪”。可以交给自动补句或一句 `departNote`，但必须有且只有一句 |
| K5 | 每月 `goalLine` | 一个月一句，校验器会数 |

## 4. 连贯性保障：删掉的字由谁接

删一句之前，先确认它被下面三件里至少一件接住，否则不删：

1. **自动落点句**（`WorkplaceTown.gd::_maybe_append_departure`）：跨区补“按 X 的安排，去 Y 吧”，同区换时段补“天亮了，还在这…接着办”，带选项的屏接在每条结果句后面。
2. **今天卡 `todayCard.lines`**：三行内写清“谁让你做什么”。
3. **走位副行 `walkNote`**：玩家在路上时的一行“为什么去”。

这三件都接不住的，说明信息只在那句话里——那句话就是 K，不能删。

### 逐屏自查（改完每屏都要过）

- 我在哪？——首拍有地点或画面，或上一屏落点已交代。
- 我为什么在这？——派活的人/理由在本屏或上一屏出现过。
- 下一步谁安排？——本屏有且只有一句落点。

## 9. 手机端 HUD 可读性（2026-11-10 真机实拍，本期落地）

5 张真机截图里 P1/P2/P3/P5 是同一类问题：**桌面宽屏写死的坐标、字号、层级，横屏手机上没跟着缩**。本节只管版式，不改任何玩家可见文案、数值或数据契约。

### 数据结构

| 状态 | 类型 | 存哪儿 | 含义 |
|---|---|---|---|
| `_activity_guide_dismissed_key` | `String` | `TownUiV2.gd` | 玩家叉掉那一屏的内容钥匙，格式 `title + "|" + note`；空串表示当前没被叉掉 |
| `_activity_guide_close` | `Button` | `TownUiV2.gd` | 活动条右上角的 ×；父面板 `mouse_filter` 保持 `IGNORE`，只有这颗按钮吃点击 |

不新增存档字段、不新增 JSON 字段。叉掉状态只在本次运行内有效，内容一变自动失效。

### 接口

#### `TownUiV2.set_activity_guide(title: String, note: String, visible: bool) -> void`

原有签名不变，行为加两条：

1. 按真实 viewport 宽度算 `guide_width = clamp(viewport_width - 40, 460, 880)`；标题 / 正文水平居中，字号 22→28 / 17→22，行高 28→32；`_layout_hud()` 仍负责整块按 viewport 居中。
2. 若 `title + "|" + note` 等于 `_activity_guide_dismissed_key`，直接隐藏并 return —— 玩家叉掉后，只要这一屏内容没变就不再弹回来。行动点或活动列表一变（key 变了）自动重新亮，因此不需要额外接主流程的换月信号。

#### `TownUiV2._on_activity_guide_close_pressed() -> void`

把当前 `title + "|" + note` 写进 `_activity_guide_dismissed_key` 并隐藏。`set_activity_scene_mode()` 退出活动场景时也要看这个 key，不能把叉掉的条又亮回来。

#### `TownUiV2._build_settings()` 的返回标题按钮

`return_button.pressed` 回调由 `_apply_settings(); title_requested.emit()` 改为 `_apply_settings(); close_view(); title_requested.emit()`。底层设置页不收掉，确认框会和底下那颗「返回标题」按钮叠在一起，看着像按钮被裁了半截。

#### `WorkplaceTown._on_ui_title_requested()`

入口处先 `_settings_panel.close()`（若开着），覆盖 `SettingsPanel` 那条信号源。

#### `WorkplaceTown._show_gate_banner()` 门槛横幅

`panel.position.x` 原为写死的 `(1920 - 620) / 2`，改为 `(get_viewport().get_visible_rect().size.x - banner_width) * 0.5`；`banner_width` 620→700，高 92→104，标题字号 23→28、副行 17→21，chip / 叉号位置同步。tween 目标 `position:y = 136` 不变。

#### `TownUiV2._layout_hud()` 心情条

`MoodMeter` 440×42 → 560×56，「心情 6/6」18→24 号，爱心 24×24 → 32×32、起点 154→196、间距 44→54；`_energy_panel` 的 y 58→72 给心情条让位。居中仍由 `(viewport_size.x - size.x) * 0.5` 负责。

#### `StartupFlow._text_content()`

引语框 / 四步条的 y 由 `body_bottom + 30 / +34` 改为 `minf(..., CONTENT_RECT.size.y - 控件高度 - 26)`，保证窄画布上正文多折几行也不会把这两块顶出内容卡片。`_layout_startup_frame()` 的整页缩放保持不变。

## 10. 报告页滚动（2026-11-10 真机实拍，P10）

十二个月走完的最终报告在手机上「没有办法上下移动」。根因有两层：PR #7（`cc71c68`）把长内容拆进「报告详情」浮层后，在 `ReportPanel.open_with()` 里把主滚动条设成 `SCROLL_MODE_DISABLED`（想做成一屏摘要），而 `_build()` 里本来是 `AUTO`；第二层是 Godot 的 `ScrollContainer` 只吃滚轮与拖滚动条，触屏在内容区拖动不会滚——即使恢复 `AUTO`，手机上仍滑不动。

本节只管滚动交互，不改任何报告文案、数值或 `Month12Report` 的装配契约。

### 数据结构 / 运行时状态

| 项 | 值 | 说明 |
|---|---|---|
| `REPORT_SCROLLBAR_WIDTH` | `const int = 24` | 两个滚动容器的 `scrollbar_width`；桌面默认太细，手指拖不住 |
| `_drag_pressed` | `bool` | 触摸被模拟成鼠标时记「左键还按着」；`close()` 里重置 |
| `ReportScroll.vertical_scroll_mode` | `SCROLL_MODE_AUTO` | 主报告；`open_with()` 打开时回到 `scroll_vertical = 0` |
| `ReportDetailScroll.vertical_scroll_mode` | `SCROLL_MODE_AUTO` | 详情浮层，显式设置，不靠默认值 |

不新增存档字段、不新增 JSON 字段。

### 接口

| 函数 | 作用 |
|---|---|
| `ReportPanel._input(event)` | 把 `InputEventScreenDrag` / `InputEventPanGesture` / 左键拖动 `InputEventMouseMotion` 的纵向位移交给 `_apply_scroll()`；`visible=false` 直接返回；**不调用** `set_input_as_handled()`，按钮与浮层点击照旧 |

| `ReportPanel._style_scrollbar(bar)` | 暖色圆头轨道 / 滑块，配色沿用 `MemoryWallPanel._style_scrollbar` |

## 12. 手机头部头像落点（2026-11-11 真机反馈 P4 复发）

### 背景

手机聊天页左上角，那颗「返回」按钮占掉面板左边 68px，头像要跟着右让 68、名字再让到 136。原来这个偏移写在**两个地方**：

- `_make_avatar()`：`box.position = Vector2(_screen_left, ...)` —— 不带 68；
- `_apply_view()`：`_header_avatar.position.x = _screen_left + (68.0 if in_chat else 0.0)` —— 带 68。

两条路径单看都对，但只要有一条先跑一条后跑就会出问题：任何重建会话的动作（`set_contact` / `_fill_thread`）都会让头像先落回 `_screen_left`，压到「返回」按钮上，直到下一次 `_apply_view()` 才被修正。玩家看到的就是「发出回复之后头像偏了」。

### 接口

| 函数 | 作用 |
|---|---|
| `PhoneInboxPanel._header_avatar_left() -> float` | 头像横坐标的唯一来源：`_screen_left + (68 if _view == "chat" or conversations.is_empty() else 0)`。`_make_avatar()` 和 `_apply_view()` 都调它，不许再各写一份 |

另外 `_build_phone_drawer()` 末尾补一次 `_apply_view()`：构建完就把视图状态摆正，不留「刚建好、还没切过视图」那一帧的旧坐标。

### 节点释放

`_fill_list()` / `_fill_thread()` / `_refresh_reply_bar()` 里原来是 `remove_child(child)` + `child.free()`。点回复时 `_on_reply_pressed` → `_refresh_reply_bar()` 就发生在**那颗按钮自己的 `pressed` 回调里**，`free()` 一个正在发信号的对象会抛 `Attempted to free a locked object`，节点还被拒收。四处统一改成 `queue_free()`：已经 `remove_child`，节点立刻离树，内存延迟释放，安全。

### 验收

- 聊天页头像 `x = _screen_left + 68`、名字 `x = _screen_left + 136`、返回键 `x = _screen_left - 4`，三者不重叠；
- 发出回复前后头像坐标一致（实测两次都是 `(148.5, 96.0)`）；
- 退回列表页头像隐藏、`x` 回到 `_screen_left`（实测 `80.5`），名字回到 `+6`；
- 点回复不再抛 `Attempted to free a locked object`；
- `--headless --quit` 0 编译错误。

## 13. 区活动面板要给右下角圆钮让位（2026-11-11 实拍）

### 现象

`AreaActivityPanel` 一直贴屏幕右下：高度按行数算，底边只留 26px。
但屏幕右下角常驻一排圆钮（手册 / 手机 / 设置，`TownUiV2._layout_bottom_buttons()`：
高 104、底边距屏幕底 28、宽 104）——**齿轮正好压在面板最后一行黄字上**。

`audit_05` 实拍：面板底部那句「现在挑一扇亮着的门进去 · 按一件东西（还剩 2 格）」
右半截被设置按钮吃掉，玩家读不到「还剩几格」。

### 规则

面板底部让出 `BOTTOM_SAFE = 140`（104 圆钮 + 28 底距 + 8 间隙），整块面板上移。
屏矮时仍保留 `maxf(120, …)` 兜底：宁可压按钮，也不许顶出屏幕上方。

同时 `_rows` 的容器高度改为跟随 `rows_height`：原来写死 280，三行是 368，
虽然 VBox 溢出也能画，但和面板高度算法对不上，改布局时容易算漂。

### 数据结构

| 常量 / 字段 | 值 | 说明 |
| --- | --- | --- |
| `AreaActivityPanel.BOTTOM_SAFE` | `140.0` | 底部让给圆钮的高度，改圆钮尺寸时同步 |
| `_root.size` | `470 × (170 + rows_height + 18 + footer_height)` | 不变 |
| `_rows.size` | `430 × max(rows_height, 1)` | 由写死 280 改为跟随行数 |

### 接口

`show_for_region(region_id, activities, remaining, maximum, points_text, footer, vertical_lift)`
签名不变，仅内部定位改成：

```
_root.position.y = maxf(120.0, viewport.y - _root.size.y - BOTTOM_SAFE - vertical_lift)
```

调用方（`WorkplaceTown._show_month12_place_list` 的 `panel_lift`）继续按原样传，不需要改。

### 验收

- `audit_05` 实拍：黄字两行完整、齿轮落在面板下沿之外；
- 一行卡时面板顶 ≈ 519（1055 高屏），不与右上「本月主线」任务卡（底 ≈ 224）相交；
- 三行卡时面板顶 ≈ 343，仍留 119 间隙；
- 面板不再和室内那叠整卡同时出现（`_show_month12_place_list` 本身二选一，`carded` 非空走整卡叠并 `hide_panel()`；截图脚本已先 `dismiss()`）。

## 14. 顶部提示条要按真实视口居中（2026-11-11 手机实拍）

### 现象

结局选项那一屏的代价提示条（「这一选有代价 / 技术，长进了一块；人也熬得够呛。」）
在横屏手机上整条偏左。玩家连着两轮反馈「上面那个还是没有居中」。

### 根因

`_show_reminder_toast()` 里写死 `(1920.0 - 600.0) / 2.0`。`project.godot` 是
`stretch/mode = canvas_items` + `aspect = expand`：手机 2400×1080 时 canvas 宽是 2400，
按 1920 居中就等于往左偏 240（屏幕上约 108px）。

同一条链路上的 `_show_gate_banner()` 早在 2026-11-10 就改成了读视口宽，只有这条被漏下。

### 接口

```gdscript
var toast_width := 600.0
panel.position = Vector2((get_viewport().get_visible_rect().size.x - toast_width) * 0.5, -100)
panel.size = Vector2(toast_width, 92)
```

### 验收

`tools/measure_band.gd` 量截图里那条深褐色的实际边界（不靠眼睛）：

```
[MEAS] ui3_02_toast_center.png｜图宽 1920｜y=80｜色带 x=670..1250（宽 581）｜中心 960.0｜图中心 960.0｜偏差 0.0
```

`tools/measure_band.gd` 是这轮加的小工具：
`--headless --script res://tools/measure_band.gd -- <png> <y> <r> <g> <b> <tol>`，
扫一行找指定颜色的连续区间，直接给左右边界与偏差。
