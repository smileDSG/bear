## 第十一轮：真机画面比例变形修复（2026-11-11 18:18）

用户真机实拍反馈「手机上的画面都被压缩了（比例变形）」。

### 根因
- 游戏设计分辨率 `window/size/viewport_width=1920 / viewport_height=1080`（16:9），`stretch_mode=canvas_items`、`stretch_aspect=expand`（本应保比例），且 `canvasResizePolicy=2`（乘 devicePixelRatio 提清晰）。
- 但 Godot Web 导出层（`entry/.../rawfile/game/index.html` 里引的 `index.js`）**完全没有 object-fit 逻辑**：grep 全库 `object-fit/cover/contain/fill` 零匹配。它只在运行时把 canvas 的 CSS 设成具体像素（`canvas.style.width=csw`、`canvas.style.height=...`、`position:absolute`），期望该比例等于显示容器比例。
- 鸿蒙外壳 `EntryAbility.ets` 开了 `setWindowLayoutFullScreen(true)`（全屏沉浸），webview 被延伸到系统底部导航条之下，实际显示区比 Godot 读到的视口更高，canvas 被纵向拉伸 → 比例变形。

### 修法（只改 HTML，不需重导 Godot Web）
- `entry/src/main/resources/rawfile/game/index.html` 的 `#canvas` 加 `object-fit: contain !important` + `width/height:100% !important` + `position:absolute;top:0;left:0`。`!important` 盖过 Godot 内联的具体像素 style，强制浏览器按画布固有分辨率比例显示，消除拉伸。代价可能是极少量黑边（letterbox）；若视口比例恰等于显示比例则无黑边。
- `GODOT_CONFIG` 与 `index.pck` 都未动，此改动只在 rawfile 的 `index.html`，故只需 `assembleHap`，无需 `--export-release`。
