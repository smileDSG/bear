# evidence-shrink：证据收缩引擎

先验分 + 若干条加权证据 → 一个后验分，证据不足时拒绝给分。纯 Python 标准库，无依赖。

## 它解决什么问题

要给一个东西打分，手上通常有两种信息：

- **先验**：某个人/模型给的大致判断（可能带偏见，但总有）
- **证据**：若干条观测信号（更客观，但数量不定、质量不一）

两种极端都错：全听先验 = 偏见；有几条证据就 fully 采信 = 武断。这个引擎用一个**随证据量增长的权重**把两者合并：

```
K      = n / (n + 5)              证据越多，K 越接近 1
行为分  = 中点 + 幅度 × 加权均值 × 载荷
后验    = 先验 + K × (行为分 - 先验)
```

n=0 时后验=先验；n=5 时一半一半；n 很大时后验≈行为分。这是最朴素的贝叶斯收缩（用先验当均值、样本量当精度）。

## 四个机制

| 机制 | 做什么 | 为什么需要 |
|---|---|---|
| 收缩 | 后验按证据量在先验/行为分之间插值 | 少量证据不该推翻先验 |
| 证据地板 | 有效证据 < 阈值时，行为分和后验都不给，只给展示分 | 不硬编结论；"没证据"≠"分低" |
| 跨情境一致性 | 按情境系数分两组判方向：同号=稳定，异号=看场合，样本不足=无法判定 | 一个只在某种场合成立的特征，不能说成稳定特质 |
| 矛盾度 | 先验与后验差距超阈值时标记 `conflict_significant` | 自评和行为打架，本身是有价值的信息 |

## 用法

```python
import engine

config = engine.default_config()

evidence = [
    {"dir": 1, "coef": 1.0, "strength": 1.0, "weighted": 1.0},
    {"dir": 1, "coef": 0.5, "strength": 1.0, "weighted": 0.5},
    {"dir": -1, "coef": 1.0, "strength": 1.0, "weighted": -1.0},
]

result = engine.shrink(prior=6.0, evidence=evidence, config=config)
print(result["posterior"], result["status"])
```

多维度批量：

```python
results = engine.shrink_many(
    priors={"dim_a": 6.0, "dim_b": 7.0},
    evidence_by_dim={"dim_a": evidence, "dim_b": []},
)
```

跑演示和测试：

```bash
python demo.py
python test_engine.py
```

### 证据字段

每条证据是一个字典：

| 字段 | 含义 | 缺省 |
|---|---|---|
| `dir` | 方向，`1` 正向 / `-1` 负向 | `1` |
| `coef` | 情境系数，0-1，越小越是"有人看着"的弱情境 | `0.75` |
| `strength` | 权重/可信度 | `1.0` |
| `weighted` | 预计算的加权值，供标准差用 | `0.0` |

`effective_n` = 各证据 `strength` 之和。证据地板按这个有效量判，不是按条数。

### 可调参数

`default_config()` 返回的参数都可覆盖，例如：

```python
config = engine.default_config()
config["k_denom"] = 10       # 收缩更慢，更信先验
config["min_evidence"] = 5   # 抬高证据地板
```

## 和评分校准的关系

这个模式可以直接迁移到 LLM-as-judge 一类场景：人类初评当先验，多个判断信号当证据，证据不足时不要输出一个看似精确的分数，而是标"证据不足"。跨情境一致性对应"模型在有/无提示时的表现是否一致"，矛盾度对应"人类评分和模型评分打架"的样本——这些都是数据筛选和质量分析的抓手。

## 来源说明

提炼自一个评分系统的后验计算模块。那里的先验是自评问卷、证据是行为事件；把具体的维度名和取数逻辑去掉后，剩下的就是通用的收缩引擎。默认参数保持与原实现一致，`test_engine.py` 里有一组数值核对。
